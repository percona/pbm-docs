# Percona Backup for MongoDB 2.16.0 ({{date.2_16_0}})

[Installation](../installation.md){.md-button}

Percona Backup for MongoDB (PBM) is a distributed, low-impact solution for creating consistent backups of MongoDB sharded clusters and replica sets, and restoring them to a specific point in time.

## Release highlights

### Backup lifecycle management

PBM now provides lifecycle management for backup rotation and retention using the grandfather-father-son (GFS) model. You can define how many daily, weekly, and monthly restore points PBM retains, then apply the policy with `pbm cleanup --lifecycle`.

Lifecycle policies support rolling and calendar strategies. The rolling strategy uses fixed 7-day and 30-day buckets. With the calendar strategy, you can select the target weekday and day of the month for weekly and monthly restore points.

The lifecycle configuration includes safeguards and cleanup controls:

- `minKeep` aborts cleanup if it would leave fewer than the specified number of successful restore points.
- `purgeFailed` controls whether PBM can remove failed and canceled managed backups.
- Logical, physical, incremental, and external backups are managed separately.
- Selective logical backups are excluded from lifecycle cleanup.
- Incremental backup chains and point-in-time recovery (PITR) data are preserved when required by a retained restore point.

### Improved backup timing visibility

PBM now records and reports backup start time, finish time, and duration. This information is available in agent logs and through `pbm describe-backup`; backup duration is also shown by `pbm list` and `pbm status`. The additional timing data makes it easier to compare backup performance and investigate operations that take longer than expected.

### Concurrent uploads to Google Cloud Storage

The native Google Cloud Storage (GCS) client now supports experimental concurrent uploads. To enable them, set `storage.gcs.clientType` to `grpc` and set `storage.gcs.parallelUploadConcurrency` to a value greater than `1`.

Concurrent uploads use temporary GCS objects that PBM composes into the final object. The configured credentials must be able to delete temporary objects. Because failed or interrupted uploads can leave temporary objects behind, configure a bucket lifecycle rule to remove them.

### Additional platform packages

PBM packages are now available for Debian 13 (Trixie) on AMD64 and ARM64 architectures, and for Red Hat Enterprise Linux 10.

## Changelog

### New features

- [PBM-1699](https://perconadev.atlassian.net/browse/PBM-1699): PBM now records backup start time, finish time, and duration, and displays this timing information in agent logs and backup-status commands.
- [PBM-1731](https://perconadev.atlassian.net/browse/PBM-1731): PBM now supports GFS backup rotation and retention policies through lifecycle-aware cleanup.
- [PBM-1736](https://perconadev.atlassian.net/browse/PBM-1736): PBM packages are now available for Debian 13 (Trixie) on AMD64.
- [PBM-1786](https://perconadev.atlassian.net/browse/PBM-1786): PBM packages are now available for Debian 13 (Trixie) on ARM64.
- [PBM-1806](https://perconadev.atlassian.net/browse/PBM-1806): PBM packages are now available for Red Hat Enterprise Linux 10.

### Improvements

- [PBM-1700](https://perconadev.atlassian.net/browse/PBM-1700): PBM now limits concurrent `collStats` queries when calculating namespace sizes before a logical backup, reducing the load generated during backup preparation.
- [PBM-1720](https://perconadev.atlassian.net/browse/PBM-1720): PBM now validates supported values for `storage.s3.debugLogLevels` and provides clearer configuration guidance for S3 request logging.
- [PBM-1749](https://perconadev.atlassian.net/browse/PBM-1749): PBM-x now supports filesystem storage and storage configuration operations.
- [PBM-1750](https://perconadev.atlassian.net/browse/PBM-1750): PBM-x now includes the foundational control-agent and worker-agent components for its minimum viable product.
- [PBM-1776](https://perconadev.atlassian.net/browse/PBM-1776): The native GCS client now supports experimental concurrent uploads through the gRPC client.
- [PBM-1780](https://perconadev.atlassian.net/browse/PBM-1780): The HMAC client for GCS is now deprecated in favor of the native GCS client.
- [PBM-1797](https://perconadev.atlassian.net/browse/PBM-1797): Updated PBM dependencies for the 2.16.0 release.
- [PBM-1804](https://perconadev.atlassian.net/browse/PBM-1804): Updated the compatibility warnings shown for Percona Server for MongoDB 8.3.

### Fixed bugs

- [PBM-1675](https://perconadev.atlassian.net/browse/PBM-1675): Fixed an issue where PBM incorrectly reported backups as incompatible when the client used an incorrect `MONGODB_URI`.
- [PBM-1689](https://perconadev.atlassian.net/browse/PBM-1689): Fixed an issue where a restore remained stuck when PBM failed to download backup chunks. PBM now reports the download failure and stops the restore.
- [PBM-1712](https://perconadev.atlassian.net/browse/PBM-1712): Fixed incomplete PBM agent cleanup after a physical restore.
- [PBM-1734](https://perconadev.atlassian.net/browse/PBM-1734): Fixed an issue where S3 debug output appeared in `pbm status` and other command output.
- [PBM-1766](https://perconadev.atlassian.net/browse/PBM-1766): Fixed an issue where `pbm describe-backup` did not report backup information for a failed logical backup.
- [PBM-1770](https://perconadev.atlassian.net/browse/PBM-1770): Fixed an issue where a logical restore with namespace remapping could trigger a MongoDB fatal assertion on Percona Server for MongoDB 8.3.
- [PBM-1771](https://perconadev.atlassian.net/browse/PBM-1771): Fixed an archive demultiplexing error that caused logical restores of time-series collections to fail on Percona Server for MongoDB 8.3.
- [PBM-1772](https://perconadev.atlassian.net/browse/PBM-1772): Fixed an `ObjectIsBusy` error during oplog replay in logical PITR restores on Percona Server for MongoDB 8.3.
- [PBM-1799](https://perconadev.atlassian.net/browse/PBM-1799): Fixed an issue where logical restores failed when using the native GCS client with split backup files and a storage prefix.
- [PBM-1824](https://perconadev.atlassian.net/browse/PBM-1824): Fixed an issue where logical backups failed while calculating namespace sizes in `getNamespacesSize`.
