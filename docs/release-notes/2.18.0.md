# Percona Backup for MongoDB 2.18.0 ({{date.2_18_0}})

[Installation](../installation.md){.md-button}

Percona Backup for MongoDB (PBM) creates consistent backups of MongoDB replica sets and sharded clusters with low impact.
PBM also supports point-in-time recovery (PITR).

PBM 2.18.0 addresses backup storage resource use and tracks improvements to recovery, restore configuration, and cloud storage.

## Release highlights

### Configure MinIO upload concurrency

The `storage.minio.uploadConcurrency` option controls concurrent uploads to MinIO and compatible storage configured with the `minio` storage type.
The option helps you balance memory consumption and upload throughput.

PBM defaults to one concurrent upload for systems with one to three CPUs.
Systems with more than three CPUs default to two concurrent uploads.
An explicit positive value overrides the default.

For details, see [MinIO storage](../details/minio.md).

## Upgrade considerations

### Review MinIO upload concurrency

Earlier PBM versions derive upload concurrency from half the available CPU count.
PBM 2.18.0 uses lower defaults to limit memory consumption.
Configure `storage.minio.uploadConcurrency` explicitly when your workload requires different upload concurrency.

### Restart PBM agents after MongoDB upgrades

[PBM-1864](https://perconadev.atlassian.net/browse/PBM-1864) tracks stale MongoDB version metadata after an in-place major-version upgrade.
An agent that remains active can record the previous MongoDB version in backup metadata.
Such backups can fail physical or incremental restore compatibility checks.

Restart `pbm-agent` on every node after upgrading MongoDB.
Take a fresh backup after restarting the agents.
Existing backups retain their original metadata.

## Changelog

### Improvements

- [PBM-1827](https://perconadev.atlassian.net/browse/PBM-1827): Added `storage.minio.uploadConcurrency` to control concurrent MinIO uploads and memory use.

### Changes pending release verification

The following tickets target PBM 2.18.0.
Their user-facing behavior requires final verification before publication.

- [PBM-1463](https://perconadev.atlassian.net/browse/PBM-1463): Addresses selective PITR inconsistencies after a database is dropped and recreated in a sharded cluster.

- [PBM-1670](https://perconadev.atlassian.net/browse/PBM-1670): Aligns logical restore cleanup of namespaces outside the backup across replica sets and sharded clusters.

- [PBM-1686](https://perconadev.atlassian.net/browse/PBM-1686): Adds selective PITR support for sharded clusters with balancer chunk split, merge, and move operations.

- [PBM-1748](https://perconadev.atlassian.net/browse/PBM-1748): Updates PBM-x agent discovery and status behavior.

- [PBM-1751](https://perconadev.atlassian.net/browse/PBM-1751): Updates PBM-x physical restore behavior.

- [PBM-1807](https://perconadev.atlassian.net/browse/PBM-1807): Adds Azure workload identity authentication as an alternative to storage account keys.

- [PBM-1820](https://perconadev.atlassian.net/browse/PBM-1820): Adds `restore.timeouts.mongodShutdown` to configure MongoDB shutdown waits during physical and external restores.
  The proposed default is 1800 seconds (30 minutes).

- [PBM-1845](https://perconadev.atlassian.net/browse/PBM-1845): Adds `--native-pitr` for external PITR restores on replica sets.
  MongoDB's native oplog recovery processes the PITR window.
  Sharded clusters remain outside the proposed feature scope.

- [PBM-1856](https://perconadev.atlassian.net/browse/PBM-1856): Adds an OCI Object Storage endpoint override for private and sovereign regions.
  Instance metadata discovery helps resolve region and realm information.

- [PBM-1864](https://perconadev.atlassian.net/browse/PBM-1864): Addresses outdated MongoDB version metadata after in-place upgrades, which can prevent physical or incremental restores.
