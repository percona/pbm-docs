# Percona Backup for MongoDB 2.18.0 ({{date.2_18_0}})

[Installation](../installation.md){.md-button}

Percona Backup for MongoDB (PBM) creates consistent backups of MongoDB replica sets and sharded clusters with low impact. PBM supports restores to a specific point in time.

PBM 2.18.0 brings updates to selective recovery, external restores, cloud storage authentication and configuration, and backup reliability.

## Release highlights

### Selective point-in-time recovery for sharded clusters

You can now restore selected namespaces in a sharded cluster to a specific point in time. PBM handles chunk splits, merges, and moves that the balancer makes during the PITR window, so the restored data stays consistent even when the balancer was active.

This release also fixes selective restores of collections whose database was dropped and recreated during oplog slicing.

To learn more, see [Selective backups and restores](../features/selective-backup.md) and [Restore a selective backup](../usage/restore-selective.md).

### Faster point-in-time recovery for external restores

On large replica sets, replaying a long PITR window after an external restore can be slow, because PBM applies oplog entries one at a time.

The new `--native-pitr` option hands this work to MongoDB. PBM adds the oplog up to your target time to the restored node, and MongoDB replays it with its own multi-threaded oplog applier as part of the restore. There's no separate `pbm oplog-replay` step.

```bash
pbm restore --external --ts=<timestamp> --native-pitr
```

Before the restore starts, PBM checks that the PITR chunks in storage reach your target time without gaps. If you don't use the option, external restores work as before.

`--native-pitr` works with replica sets only. Sharded clusters aren't supported.

On multi-terabyte replica sets, `mongod` can take more than 30 minutes to shut down after the replay. If your restore times out at this stage, increase [`restore.timeouts.mongodShutdown`](../reference/restore-options.md#restoretimeoutsmongodshutdown).

For more about external restores, see [Restore from a snapshot-based backup](../usage/restore-external.md).


### More control over storage and restores

You can now authenticate to Azure Blob Storage with workload identity instead of a storage account key. Native OCI Object Storage also supports custom realm domains and home regions, so you can use it in Oracle Alloy and other sovereign or private regions. See [Storage configuration](../details/storage-configuration.md).

For MinIO and other S3-compatible storage that uses the `minio` storage type, the new [`storage.minio.uploadConcurrency`](../reference/configuration-options.md#storageminiouploadconcurrency) option sets how many parts PBM uploads in parallel. Higher values can speed up uploads but use more memory:

```bash
pbm config --set storage.minio.uploadConcurrency=4
```

Physical and external restores used to fail if `mongod` took longer than 30 minutes to shut down, which can happen on large data sets. You can now raise that limit with [`restore.timeouts.mongodShutdown`](../reference/restore-options.md#restoretimeoutsmongodshutdown):

```yaml
restore:
  timeouts:
    mongodShutdown: 3600
```

## Upgrade considerations

### Lower default upload concurrency for MinIO storage

PBM now uploads one or two parts in parallel to `minio` storage by default, depending on the number of CPUs. Earlier versions used half the available CPUs, which could use a lot of memory on large hosts. If uploads are slower after you upgrade, increase `storage.minio.uploadConcurrency`.

### Restart PBM agents after upgrading MongoDB

If you upgrade MongoDB to a new major version in place while `pbm-agent` keeps running, the agent keeps reporting the old version. New backups record that old version in their metadata, and PBM refuses to use them for physical or incremental restores on the upgraded cluster. These backups still finish with the `done` status, so the problem only shows up when you try to restore.

To avoid this, restart `pbm-agent` on every node after you upgrade MongoDB, and then take a new backup. Backups taken before the restart keep the old version. This issue is tracked in [PBM-1864](https://perconadev.atlassian.net/browse/PBM-1864).


## Changelog

### New features

- [PBM-1686](https://perconadev.atlassian.net/browse/PBM-1686): Improved selective logical restore consistency in sharded clusters when oplog slicing includes chunk split, merge, and move operations.
- [PBM-1807](https://perconadev.atlassian.net/browse/PBM-1807): Added support for Azure workload identity authentication for backup storage.
- [PBM-1845](https://perconadev.atlassian.net/browse/PBM-1845): Added the `--native-pitr` option for external point-in-time restores on replica sets. This mode uses MongoDB's native oplog recovery and is not supported for sharded clusters.

### Improvements

- [PBM-1670](https://perconadev.atlassian.net/browse/PBM-1670): Aligned logical restore cleanup behavior for replica sets and sharded clusters, addressing namespaces not included in the backup.
- [PBM-1748](https://perconadev.atlassian.net/browse/PBM-1748): Updated PBM-x agent discovery and status handling.
- [PBM-1751](https://perconadev.atlassian.net/browse/PBM-1751): Updated PBM-x physical restore handling.
- [PBM-1820](https://perconadev.atlassian.net/browse/PBM-1820): Made the MongoDB shutdown wait configurable through `restore.timeouts.mongodShutdown`, with a default of 30 minutes for physical and external restores.
- [PBM-1827](https://perconadev.atlassian.net/browse/PBM-1827): Added `storage.minio.uploadConcurrency` to control the number of concurrent MinIO uploads and manage memory consumption.
- [PBM-1856](https://perconadev.atlassian.net/browse/PBM-1856): Added OCI Object Storage configuration for private and sovereign regions, including a custom endpoint and instance-region metadata discovery.

### Fixed bugs

- [PBM-1463](https://perconadev.atlassian.net/browse/PBM-1463): Addressed inconsistent selective logical restores in sharded clusters when a database was dropped and recreated during oplog slicing.
- [PBM-1864](https://perconadev.atlassian.net/browse/PBM-1864): Addressed stale MongoDB version metadata retained by `pbm-agent` after an in-place MongoDB upgrade, which could prevent physical and incremental restores.
