# Percona Backup for MongoDB 2.17.0 ({{date.2_17_0}})

[Installation](../installation.md){.md-button}

Percona Backup for MongoDB (PBM) is a distributed, low-impact solution for creating consistent backups of MongoDB sharded clusters and replica sets, and restoring them to a specific point in time.

PBM 2.17.0 improves restore reliability for time-series collections and physical point-in-time recovery (PITR), provides clearer errors for failed incremental backups, and updates Go and third-party dependencies.

## Release highlights

### More reliable physical point-in-time recovery

Physical PITR now applies index creation, deletion, and modification operations recorded in the oplog. Indexes created or dropped during the recovery interval are reflected in the restored data.

PBM also disables the TTL monitor in the temporary `mongod` processes used during physical restores. This prevents TTL deletions from interfering with oplog replay and causing duplicate key errors in collections with unique indexes. The TTL monitor resumes its normal behavior when MongoDB starts after the restore.

Another fix prevents physical PITR from waiting indefinitely when oplog replay and restore status reads compete for the same storage download buffer.

For details about physical PITR, see [Restore to a point in time from a physical backup](../usage/pitr-physical.md).

### Improved restores of time-series collections

PBM fixes index creation errors during point-in-time recovery of time-series collections and oplog replay validation errors during logical restores. These fixes address `IllegalOperation` and `DocumentValidationFailure` errors, including failures when time-series collections were backed up under high write throughput.

### Clearer incremental backup errors

When an incremental backup fails on a shard, PBM now reports the underlying shard error instead of a generic convergence timeout. For example, if the previous incremental backup was made on another node, the error explains that the incremental backup history is unavailable and that you must create a new base incremental backup.

## Changelog

### Improvements

- [PBM-1775](https://perconadev.atlassian.net/browse/PBM-1775): Improved error reporting for failed backups in sharded clusters. PBM preserves and reports the failing shard's error, including missing incremental backup history, instead of a generic convergence timeout.

- [PBM-1821](https://perconadev.atlassian.net/browse/PBM-1821): Updated Go to 1.27.1 and refreshed third-party dependencies, including MongoDB Database Tools and cloud storage SDKs.

### Fixed bugs

- [PBM-1762](https://perconadev.atlassian.net/browse/PBM-1762): Fixed `IllegalOperation` errors when creating indexes during point-in-time recovery of time-series collections. PBM now tracks pending index definitions when collections are renamed and uses the appropriate collection namespace for index creation.

- [PBM-1763](https://perconadev.atlassian.net/browse/PBM-1763): Fixed `DocumentValidationFailure` errors when replaying oplog entries for time-series collections during point-in-time recovery.

- [PBM-1779](https://perconadev.atlassian.net/browse/PBM-1779): Disabled the TTL monitor during physical restores to prevent TTL deletions from interfering with PITR oplog replay and causing duplicate key errors in collections with unique indexes.

- [PBM-1795](https://perconadev.atlassian.net/browse/PBM-1795): Fixed a storage download deadlock that could prevent a physical PITR restore from completing. Oplog replay now uses a separate storage instance so it cannot block restore status and heartbeat reads.

- [PBM-1802](https://perconadev.atlassian.net/browse/PBM-1802): Allowed deletion of backups with stale heartbeats even when their metadata still reports a starting or running state. Previously, `pbm delete-backup` rejected these backups as still in progress.

- [PBM-1813](https://perconadev.atlassian.net/browse/PBM-1813): Fixed logical restore failures for time-series collections backed up under high write throughput, where oplog replay could fail with bucket data validation errors.

- [PBM-1817](https://perconadev.atlassian.net/browse/PBM-1817): Fixed physical PITR restores that did not apply index creation and deletion commands from the oplog. PBM now also applies index modifications recorded by `collMod`.
