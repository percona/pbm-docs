# Percona Backup for MongoDB 2.17.0 ({{date.2_17_0}})

[Installation](../installation.md){.md-button}

Percona Backup for MongoDB (PBM) is a distributed, low-impact solution for creating consistent backups of MongoDB sharded clusters and replica sets, and restoring them to a specific point in time.

PBM 2.17.0 improves restore reliability for time-series collections and physical point-in-time recovery (PITR), provides clearer errors for failed incremental backups, and updates Go and third-party dependencies.

## Release highlights

### Enhanced physical point-in-time recovery

Physical PITR now replays index operations recorded in the oplog, including index creation, deletion, and modification. Previously, it skipped them. Any index you create or drop between the backup and the restore target time now appears correctly in the restored data.

PBM automatically disables the TTL monitor for the duration of physical restores, with or without PITR. Before this change, TTL deletions could interfere with oplog replay and cause duplicate key errors in collections with unique indexes. TTL monitoring resumes by default when you start MongoDB after the restore.

This release also fixes a deadlock that could leave physical PITR waiting indefinitely. Oplog replay and restore status reads competed for the same storage download buffer, so neither could move forward. Oplog replay now uses its own storage instance.

For details about physical PITR, see [Restore to a point in time from a physical backup](../usage/pitr-physical.md).

### Improved restores of time-series collections

PITR no longer fails with `IllegalOperation` errors when it creates indexes on time-series collections. PBM also bypasses document validation during oplog replay to prevent `DocumentValidationFailure` errors in logical restores, including PITR, of time-series collections backed up under high write throughput.

!!! warning "Time-series collections with expiration"

    A logical restore, including PITR, can still fail if a time-series collection uses `expireAfterSeconds`. The TTL monitor can delete buckets that oplog replay still needs. Before restoring an affected backup, manually disable [`ttlMonitorEnabled` :octicons-link-external-16:](https://www.mongodb.com/docs/v8.0/reference/parameters/#mongodb-parameter-param.ttlMonitorEnabled){:target="_blank"} on each data-bearing `mongod` in the target deployment and keep it disabled for the duration of the restore. Record each instance's original value and restore it when the operation ends, even if it fails.

    See [Restore from a logical backup](../usage/restore.md) for the restore procedure.

### Clearer incremental backup errors

When an incremental backup fails on a shard, PBM now reports the underlying shard error instead of a generic convergence timeout. For example, if the previous incremental backup was made on another node, the error explains that the incremental backup history is unavailable and that you must create a new base incremental backup.


## Changelog

### Improvements

- [PBM-1775](https://perconadev.atlassian.net/browse/PBM-1775): Improved error reporting for failed backups in sharded clusters. PBM preserves and reports the failing shard's error, including missing incremental backup history, instead of a generic convergence timeout.

- [PBM-1821](https://perconadev.atlassian.net/browse/PBM-1821): Updated Go to 1.27.1 and refreshed third-party dependencies, including MongoDB Database Tools and cloud storage SDKs.

### Fixed bugs

- [PBM-1762](https://perconadev.atlassian.net/browse/PBM-1762): Fixed `IllegalOperation` errors when creating indexes during point-in-time recovery of time-series collections. PBM now tracks pending index definitions when collections are renamed and uses the appropriate collection namespace for index creation.

- [PBM-1763](https://perconadev.atlassian.net/browse/PBM-1763): Fixed `DocumentValidationFailure` errors when replaying oplog entries for time-series collections during point-in-time recovery. For collections with `expireAfterSeconds`, manually disable the TTL monitor before the restore and keep it disabled for the duration of the restore. Restore its original setting afterward, even if the restore fails.

- [PBM-1779](https://perconadev.atlassian.net/browse/PBM-1779): PBM now automatically disables the TTL monitor for the duration of physical restores, with or without PITR. This prevents TTL deletions from interfering with oplog replay and causing duplicate key errors in collections with unique indexes.

- [PBM-1795](https://perconadev.atlassian.net/browse/PBM-1795): Fixed a storage download deadlock that could prevent a physical PITR restore from completing. Oplog replay now uses a separate storage instance so it cannot block restore status and heartbeat reads.

- [PBM-1802](https://perconadev.atlassian.net/browse/PBM-1802): You can now delete backups with stale heartbeats, even if their metadata still shows a starting or running state. Previously, `pbm delete-backup` rejected these backups as still in progress.

- [PBM-1813](https://perconadev.atlassian.net/browse/PBM-1813): Fixed logical restore failures for time-series collections backed up under high write throughput. Oplog replay could fail with bucket data validation errors.

- [PBM-1817](https://perconadev.atlassian.net/browse/PBM-1817): Fixed physical PITR not applying index creation and deletion commands from the oplog. PBM now also applies index changes made with `collMod`.
